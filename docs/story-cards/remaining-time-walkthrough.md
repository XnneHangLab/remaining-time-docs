# 序章与31张遗物任务卡 · 推进卡点记录

本次以**序章 + 扩展版 S01 + S02–S31**为目标，不用旧六步 S01 的完成代替扩展版完成。游戏依据为 `469e096`（PR #111 合入后的 dev），任务卡依据为文档 `75c6c81`。记录日期为工作环境日期 2026-09-24。后续游戏或卡片变动后，下面的结论需要重新核对。

**实测能走通的是序章和旧六步 S01；继续走到公共厨房与 Rowan 交谈，没有 S02 可接。扩展版 S01 和 S02–S31 尚未加载为游戏任务，不能声称全线通关。** 本次读取并解析了32张目标卡、194个阶段，后30张卡采用共同的六阶段模板；逐卡表保留各自不同的证物、来源、结论和替代路径。

## 推进方式与实际终点

通过实际房间包和游戏引擎，从原始出生点执行移动、过门、交互与选择；不注入解锁变量，不跳写任务进度，不传送。复用现有寻路检查走到交互站位，再调用与游戏一致的命令。检查了拿取、暂存、取消、重复请求，以及拿取后恢复存档继续交付和完成后的回放一致性。

这是**引擎流程执行 + 任务卡／内容／源码核对**，不是浏览器手动试玩。画面遮挡、按钮视觉、鼠标命中、音效、镜头及操作手感未验收。S02之后为逐卡桌面推演：假定到达该卡入口，列出首先会卡在哪里以及完成语义还缺什么，不伪造运行进度。

## 1. 美术资产缺哪些

### 已有资产先复用

实际包有26个房间、54个单向出口；404、回廊、厨房、计时所、接待会等基础空间已经存在。Rowan、Ash、Mara、Adrian、Meridian、Celeste、Noel、Iris、Rhea、Milo、Lyra、Silas及常用居民都有对应人物素材或实体。不能把所有未接剧情的NPC都算作“缺人物美术”。

已确认门牌PNG、404旧记录与柜子可用；厨房已有桌椅、桌布、杯碗、终端、配方纸等独立PNG。回廊有仿生雨燕人物素材。**现有普通桌布不等于“四人折痕餐垫”，普通杯子不等于“磨平缺口杯”，雨燕站立图也不等于可验证医疗部件。**这些是复用候选，需要核对证物特征。

## 2. NPC缺少哪些ability

当前引擎接受 `movement`、`dialogue`、`shop`、`schedule`。但房间manifest没有加载NPC能力文件，主要通过Scene实体与Story交互提供现有行为；大多数剧情NPC只是固定位置加空白菜单。**引擎支持某种ability、人物配置了它、该任务真的用上它，是三件不同的事。**

| 需求 | 当前边界 | 最小补齐／验收 |
| --- | --- | --- |
| 介绍、询问、提供固定记录、给线索 | 已有条件对白、话题、确认、线索来源与首次招呼 | 属于内容缺口，先给Rowan／Mara／Adrian等编排，不新增一个“证人”ability |
| 证词拒绝、离开、归零后的替代 | 可用布尔条件编写固定分支；没有任务专属可用状态或生命归零后来源转换 | 明确当前陈述／既有签名／公共档案及缺席原因；NPC不可交互时仍能找到已存在兜底，不能捏造新证词 |
| N-07扫描、校准和解封 | 能发固定线索；没有结构化材料版本、签名匹配、可解封字段 | 三来源齐备才校准，哈希不符不解封；原地扫描不加原件到背包。能力主体是证据系统，N-07是交互入口 |
| Ash／机构接受代管并签收 | 能扣玩家物品；没有NPC持有账、柜中实体与独立回执 | 缺原件拒绝；只有选定保管人可签收；成功后原件唯一持有人、回执、任务结果原子更新 |
| Adrian查询／人工打印、Meridian公开索引 | 能对话，不能验证凭证与选择最小披露字段 | 两条来源得到等价最小记录，人工件标人工来源；私人正文仍封存，不需要先做真实打印动画 |
| Noel引见、住户试装、跟随协作 | 引擎有显式路线，主要剧情NPC未启用移动；没有自动寻路、动作完成事实或生成／显示物件的通用效果 | 若保留前厅引见，给确定站位或明确路线与到达条件；开始走路不能等同到达；试装和门牌出现分别计状态 |
| 修复／关闭／拆解、播种／供电／开通道 | 无任务物件状态转换与业务完成事实 | S24、S14、S16先明确实际操作与结果，再加最小效果。播放duty动画不代表完成维修或治疗 |
| 访问许可、限定用途、撤回 | 普通对话条件不是资料授权模型 | 执行读取时重验对象、用途和当前许可；撤回后不能继续读受限缓存。不要仅在UI隐藏按钮 |
| 陌生人接触信号 | 已有首次招呼记录；没有 `+1/0/-1/null` seed值和语义 | 第一次确认写入一次；取消、读档、重复交谈不改写。熟悉程度与任务接受、证据取得分离 |

这些任务主要要求**证物和来源的可靠交接**，不要求先做NPC自由决策Agent。餐饮、演出、教学也不是本次主线的必要能力：调查厨房账或排练带可以用已有记录交互，不能因此把实验分支玩法整套合回主线。

## 3. 任务系统是否可以完整引导

**目前可以引导一个有明确实体／场景目标的线性流程，不能完整覆盖扩展S01和31卡并行调查。**

### 已具备

- 明确实体或场景目标的默认标记；跨房间按门连接找到第一段出口。
- 当前阶段的背景、行动描述、任务更新提示、未来阶段隐藏。
- 四类事实：移动成功、开始交互、确认选项、进入场景。
- 有序步骤、多个独立任务同时消费事实、去重计数、已确认来源文本、读档／回放。
- 显式选项条件限制操作；拿取和交付失败可回滚。

## S01到S02的过渡

本次在**任务卡层**补了一个可审阅的过渡，不把尚未实现的扩展S01伪装成已经能接S02：

1. 扩展S01在实际交付回执确认后，由N-07提示可去公共厨房找Rowan问折叠餐垫。404、Ash、公共证物库三种交付结果均应有这个提示，不追加一次必须回404的跑腿。
2. 厨房入口明确为 `low-kitchen / rowan`。先进入餐垫话题，玩家选择调查才接受，稍后再来不写入接受状态。
3. Rowan只提示先看折痕、再核对座位扣时记录与居民说法；此时不宣布“缺席者被计入”。
4. S02仍可自行到访接受，**不把S01完成改成硬前置**。这是推荐游玩顺序，保留31条主线可并行的约定。
5. S01材料、保管人和公开选择不能替S02完成材料，也不能决定是否允许调查厨房。

在正式游戏接入前，还要绑定餐垫实体、当晚账目与Mara兜底账，明确实际持有人；这些卡片原有TODO不能由开发者静默猜定。S01-00与序章结尾的重复出门也需要单一交接点。

## 建议接下来的实际推进顺序

1. **先修序章与共享引导的现有问题**：旧记录和N-07提前揭露、出门交接、话题入口图标；补“查看公共物件”的目标。这些不依赖新美术。
2. **把扩展S01作为能力验收样板**：落实扫描／暂借、Ash／Mara替代、计时所公开查询、N-07材料校准、接待会主张、三栏草稿和三处真实交付。每条分支保留取得方式和持有人，不先复制31套任务。
3. **接S02并验证并行／复用**：厨房入口、餐垫、账目、证词和兜底；验证先拿账、后看餐垫仍能汇合，且S01交付选择不影响入口。
